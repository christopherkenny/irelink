# irelink

This is a project to test the capabilities to translate large open source projects to other programming languages with LLMs.
After the first commit, all code changes will be done with GitHub Copilot, primarily using Anthropic models.

The goal is to take splink, an MIT-licensed record linkage package written in python, into irelink, a downstream MIT-lcensed record linkage package in R.
As it is a derivative package, we can copy the tests and simply rewrite them in our syntax.
R has a robust system of SQL backends that can be used for similar database operations.

Why do this?
R is fundamentally more powerful, ergonomic, and efficient as a data science langauge.
This provides a serious test of if we can take a good tool in a bad langauge and turn it into a great tool in a great language.
Beyond that, how well can we extend opensource using LLMs by translating tools?

# Project stages

1. Scope and structure
    a. handle the R basics like description and define what splink does
    b. research DBI and dbplyr backends for compatability
2. Planning
    a. Create references to be stored in `inst/refs` on splink itself
    b. Define the R interface for irelink
    c. Write the target roxygen for irelink
    d. Verify that this software coverage is sufficient to cover all core features
    e. Organize all functions into stages from core functionality to broader pieces
    f. Write a full, detailed implementation plan for stages 3--7
3. Test implementation
    a. For the desired interface, write every test from splink into irelink
    b. Note the stage for every test
4. R code implementation
    a. In steps, implement each function
5. Code simplification
    a.
6. Test review
    a. Fill in tests for R-style aspects that splink wouldn't have to test for
7. Performance review
    a. R is generally faster than python and, for most things, speed is dependent on SQL backends
    b. Check for pure pythonic translations instead of R-style vectorized implementations
